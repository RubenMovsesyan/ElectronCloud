ElectronCloud

An electron cloud renderer: what an electron “looks like”. Built on GameEngine, which is developed alongside it.

What this is

src/main.cpp opens a fixed 1920×1080 window and draws ElectronCloud’s own renderer through GameEngine’s graphics::Presenter. The renderer is a CUDA ray marcher; today it draws a single sphere. 

app::Application<ElectronCloud> app{
    {.width = 1920, .height = 1080, .title = "ElectronCloud", .resizable = false}, argc, argv};
app.run();

The app is a State type (ElectronCloud, below): app::Application<S> builds it once the GPU is up (its constructor is init), calls frame() every frame, and destroys it before the GPU goes down (its destructor is cleanup).

Building

git submodule update --init --recursive
./run           # bootstrap ./build if needed, build, launch (needs the CUDA toolkit)
./run clean     # wipe .build first

build.cpp compiles GameEngine’s sources directly (it does not run the engine’s own build.cpp), generates the engine’s shader header with the engine’s bundled sokol-shdc, and links everything into .build/bin/electron_cloud.

The renderer

renderer::ElectronCloudRenderer lives in src/renderer/, not in GameEngine: it is specific to this project. It satisfies GameEngine’s graphics::Renderer concept, so graphics::Presenter draws it like any engine renderer: 

struct ElectronCloud {
    renderer::ElectronCloudRenderer renderer;
    graphics::Presenter presenter;

    explicit ElectronCloud(app::Context&) {}
    void frame(app::Context&) { presenter.present(renderer); }
};

It is a CUDA ray marcher. The State owns a fly Camera (WASD, Space/Ctrl, ESC toggles mouse-look), a renderer::Sphere and the march settings: 

renderer::Sphere sphere{.center = Eigen::Vector3f::Zero(), .radius = 1.0f};
renderer::ElectronCloudRenderer renderer{renderer::RaymarchSettings{.step = 0.1f, .max_distance = 5.0f}};

void frame(app::Context& context) {
    ...
    renderer.beginFrame(camera);
    renderer.submit(sphere);
    presenter.present(renderer);
}

Every frame the raymarch kernel (electron_cloud_renderer.cu) marches one ray per pixel from the camera, step at a time, until checkRay() reports a hit (for now: the point is inside the sphere) or the ray is max_distance away — 50 steps at 0.1 and 5. Hits are shaded by distance, so the step size shows as rings. 

__device__ bool checkRay(float3 position, const RaySphere& sphere) {
    const float3 offset = position - load3(sphere.center);
    return dot(offset, offset) <= sphere.radius * sphere.radius;
}

CUDA can only share buffers with Vulkan in this engine, not images, so the kernel writes RGBA8 pixels into a shared buffer and a fullscreen pass (shaders/electron_cloud.glsl) copies them into the image render() returns. Two timeline semaphores keep CUDA and Vulkan off the buffer at the same time: CUDA waits for the previous frame’s copy to finish before writing, and the copy waits for CUDA. CUDA runs on the render thread, inside render().

Working on GameEngine

external/GameEngine is a full clone of RubenMovsesyan/GameEngine. Engine features ElectronCloud needs are written there, following the engine’s own AGENTS.md (and its docs), committed inside the submodule, pushed to the engine’s remote, then the new submodule pointer is committed here. A new engine source file must be added to both the engine’s build.cpp and the engine_sources list in ours.
